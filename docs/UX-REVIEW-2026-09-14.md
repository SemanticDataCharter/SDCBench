# SDCBench usability and visual review, pass one

**Date:** 2026-09-14. **Build reviewed:** 4.0.0-beta.2 frontend, rendered in a browser against
a mocked bridge (canned sign-in, projects, wallet and a search that returns Default-library
rows). **Method:** static read of `index.html`, `style.css`, `canvas.js`, `main.js`, plus
scripted screenshots of nine states at 1280x800. **Not covered:** the feel of dragging,
Blockly under a real pointer, WebKitGTK rendering differences, sign-in against production.
Pass two is Tim at the keyboard doing steps 1 to 3 of the pizza tutorial cold.

Screenshots are in `docs/review/2026-09-14-*.jpg`, named by state.

## The verdict in one paragraph

The bones are right and the copy is honest. The sign-in card says exactly what happens to the
key, the cost dialog shows the price and the balance before anything is charged, the
requirement gate names the fields that block a send, and the snap rules make invalid
structure impossible rather than merely discouraged. What is not right yet is the first two
minutes and the look. A new user lands on a large empty grid with a small block in the corner,
types a search on the right edge and gets results on the left edge, and starts with a search
scope that returns nothing. Visually the bench is a competent Blockly default in a neutral
grey that does not belong to the two websites, and the blocks carry empty sockets and bays that
make a seven-field model look busier than it is. Nothing here is more than a day or two; the
first five items below are hours.

## Findings, in the order a first-time user meets them

### 1. "Search in" starts on the user's own empty project [high, small]

`loadProjects` fills both selectors with the user's default project. A new account's default
project has nothing published, so the first search returns "No published components match"
and the reuse lesson dies on contact. `search.jpg` shows the selector reading "Pizzeria" while
the results are library components; against production they would be empty.

Fix: default "Search in" to the project flagged `is_default_library`, and only fall back to
the build project if there is no library. One line in `loadProjects`.

Tim: If I recall, when a user has a valid API key the search will be across the user's selected project + all public projects. So, this wouldn't need a fix.

> Checked against SDCStudio (`component_list_view` and `_build_component_union_sql`): the
> server searches everything the user can see when no `project` is sent, exactly as recalled.
> The bench always sent the selected project, and the SQL then adds `t.project_id = %s`, so
> the search narrowed to that one project. **Resolved** by a default "Everything I can see"
> option that sends no project; a single project still narrows. No server change.

### 2. The reuse loop runs across the whole window [high, medium]

The search box is in the right panel. The results appear as a flyout on the far left, 1,000
pixels away, and the panel text admits it: "Matches appear in the Reuse tab on the canvas".
The flyout also opens over the seeded model at x=40 (`search.jpg`), so the user's own blocks
disappear behind the results.

Fix, two parts. Move the search box into the toolbox side so typing and results are adjacent
(a search input above the New/Reuse categories, or a results list in the panel whose rows are
themselves draggable). And seed the model further right, or open the flyout without covering
column one. The Blockly `toolboxPosition` and a wider toolbox with an embedded input are the
cheap path; a draggable panel list is the better one.

Tim: Do the better one.

> **Done.** Results render as a list under the search box; click adds to the selected group
> (or the root), drag drops onto the canvas. Units and ranges attach to the selected field.
> The Reuse flyout still mirrors the results but is no longer opened for the user, so it
> never covers the model.

### 3. The empty canvas gives no first move [high, small]

`fresh.jpg`: a locked Model block with an empty `contains` slot in the corner of a 900-pixel
grid, and a panel that says "Your model is valid." An empty model is not valid in any sense a
user cares about, and nothing says what to drag where.

Fix: an on-canvas hint beside the empty slot ("Drag a field from New, or search the library
and drag from Reuse") that disappears on the first drop, and a status line that reads "Empty.
Add fields." until there is content. Both are text; no new mechanics.

### 4. The empty `units` socket and `ranges` bay make every number field look broken [medium, small]

`canvas.jpg`: `Quantity` and `Bake Temperature` each carry an empty puzzle socket labelled
`units` and a large empty `ranges` bay underneath. Four of the seven new fields in the pizza
model show this. Ranges are optional at the bench and the guide says the modeler adds them in
SDCStudio, so the bay is an invitation to do work that belongs elsewhere, and it doubles the
block height.

Fix: do not render the `ranges` input until a range is dragged onto the block (or behind a
small "+ ranges" affordance). Keep `units` for quantified types, since SDCStudio cannot save a
number without one, but render the empty socket as a labelled placeholder ("units: none yet")
rather than a bare notch. Both are in the field mutator.

### 5. A missing requirement is invisible on the canvas [high, small]

The send button refuses and lists the fields (`blocked.jpg`), which is good. But nothing on
the canvas marks which blocks are missing one; the user has to read the list and hunt. Blockly
has a per-block warning icon (`setWarningText`) that shows a small triangle and a tooltip.

Fix: set a warning on every new field without a requirement, clear it when text is entered.
Then the blocked message can be shorter, because the canvas shows it.

### 6. Reuse is marked by a small arrow glyph [medium, small]

Reused blocks read "↩ Text · Phone Number". The arrow is the only signal and it is a
seven-pixel glyph at the block's left edge. Colour is reserved for type, correctly, so the
reuse marker needs to be a shape or a word.

Fix: replace the glyph with a short label pill ("reused") or give reused blocks a distinct
left edge. Also drop the middle dot separators; "Text · Phone Number" reads as two things.

Tim: label pill

> **Done.** A small "reused" pill drawn as an SVG image field; middle dots removed.

### 7. The three greens do not read as three [medium, small]

`#2e8b57`, `#2f9e8f`, `#6a9a3f` for plain, ordered and quantified data. Side by side on
`canvas.jpg` they are one green with slight drift, and the legend exists only in Help. Either
the distinction matters, in which case pick three hues a colour-blind user can separate and
show a legend on the canvas, or it does not, in which case use one green and let the type
badge carry the meaning. The badge already does. Recommendation: one green.

### 8. The look is not the house look [medium, medium]

The bench uses a neutral grey (`#0f1115`, `#171a21`) with a Google-blue accent (`#4f8cff`).
Both websites use a navy ground (`#050b14`, surface `#0a2342`), one teal accent (`#2ca58d`)
and amber only as a signal colour (`#f0a500`). The bench's amber is already reserved for units
and ranges, which is a reasonable use of the signal colour. The blocks use Blockly's classic
renderer, whose puzzle-piece notches read as Scratch.

Fix: swap the six CSS tokens to the site palette (ground, surface, text, muted, teal accent);
switch Blockly to the `zelos` renderer (rounded, quieter connectors) and define the theme from
the same tokens; set primary buttons teal. Half a day, mostly tokens. This is the tie-breaker
from the brand rule: calm and exact, not playful.

### 9. Developer artefacts are visible to the domain expert [low, small]

The collapsed "Structure" panel prints the JSON tree; the header badge shows "SDCBench
4.0.0b2" in the green "ok" style, which reads as a status rather than a version. The guide
overlay is a raw render of the Markdown with no in-page navigation.

Fix: move Structure behind an "Advanced" disclosure or remove it; show the version in the
muted style, without the success colour; add a contents list at the top of Help.

Tim: add the Advanced display

> **Done.** "Structure" is now "Advanced", with one line saying what it is. Version badge no
> longer uses the success colour. Help has a contents list built from its headings.

### 10. Copy, small things [low, small]

- Em dashes in placeholders and status lines ("What this model captures — used when it's
  finalized"). House rule is no em dashes.
- "Send to SDCStudio" is the right verb; the dialog then says "This creates a draft data
  model". Keep one verb in both places.
- The cost line counts the pre-seeded root group as a new component ("10 new components").
  True, and the user did not make it. Say "3 groups and 7 fields" so the count is checkable.
- "Building in" and "Search in" are clear. "Saved drafts…" as a select placeholder is fine.
- Delete is "drag off to the left", stated only in Help. A trashcan or a one-line hint on the
  canvas would save the question.

## What is good and should not change

- The sign-in card. Three sentences that answer the security question before it is asked.
- The cost dialog: price, breakdown, balance, and a funding link when short. This is the
  provable-restraint posture in a UI.
- The requirement gate. Refusing to send without the handoff text is the whole product idea
  enforced at the right moment.
- Snap rules from the composition model. Invalid structure cannot exist.
- Local save with an automatic directory. No plumbing.
